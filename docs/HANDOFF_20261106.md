## 2. 배경 — 무엇을, 왜 하나
논문 ICRA2027 "EE-GEAR"(프로젝트 파일 `ICRA2027_도구활용.pdf`)의 근거를 보강하는 작업이다.

- **Table III (task success)**: w/o Reasoner가 8개 태스크 전부 0.0으로 나왔는데, Reasoner 제거 탓인지 검증할 수 없었다.
  - 기존 성공 판정은 "M5가 예외 없이 끝남"이었다.
  - 기존 w/o Reasoner는 VLM이 EE를 직접 고르는 구조라, 8개 중 6개가 M2 JSON 검증에서 멈췄다.
- **Table II (Fixed-EE object coverage)**: 수치가 재현되지 않았다.
  - 정의: 잡힌 물체 / 태스크 전체 물체 ("covered if grasped successfully with that EE").
  - scripted grasp 레지스트리가 좁아서, 규칙상 정당한 EE를 골라도 `SCRIPTED_GRASP_EE_INFEASIBLE`로 실행 전에 멈췄다.

## 3. 완료한 것
- **조건 매핑** (`--condition`): `full` = Ours, `wo-reasoner` = `--grounding-mode without_reasoner`, `wo-planner` = `--planner-mode without-planner`, `wo-grounding-legacy` = 구 without_grounding.
- **w/o Reasoner 재구현** (`src/tuj/ablations/vlm_prior.py`, `scripts/run_without_reasoner.py`): Reasoner 측정값(치수·질량·재질·마찰·틈)만 VLM 추정(이미지+이름)으로 바꾸고, EE 규칙(`m1_scene/ee_rules.evaluate_ee`), M2, G_k, M4, M5는 Full 코드를 그대로 쓴다. 위치·bbox는 시뮬레이터 값이다. 팀원 v3에서 ee_fallback을 제거했다: 판정 규칙을 조건 간 동일하게 두기 위해서이고, VLM 추정 탓에 feasible EE가 없으면 M4 NoCandidate가 나는데 이것을 정당한 실패로 본다.
- **실패 분류 + 공통 결과** (`m5_motion/failure_taxonomy.py`, `run.py run_m5_with_retries / write_run_result`): `failure_stage`는 planning | execution | goal | evaluation | infrastructure. 결과는 모든 조건에서 `run_result.json` 같은 스키마로 남는다.
- **성공 판정** (팀원, task-goals-v1, `docs/task_goal_evaluation.md`): success = exec_success ∧ goal_success.
- **API 장애 처리** (11/06, `src/tuj/common/api_retry.py`):
  - 모든 LLM 클라이언트(M1 SiPhy, M2, M5 Gemini/OpenAI)를 재시도 프록시로 감쌌다. 대상은 429/5xx/타임아웃/"high demand"이고, 백오프는 10→120초, 기본 6회.
  - 다 실패하면 `API_UNAVAILABLE` 오류가 나고 `failure_stage=infrastructure`로 분류된다. 이어서 `run.py --api-reruns`(기본 2, 대기 `TUJ_API_RERUN_WAIT_S`=180초)가 M5를 다시 돈다.
  - 그래도 실패하면 `success=null`, `rerun_required=true`로 남는다. 이런 trial은 make_table3이 집계에서 빼고, batch를 `--skip-done`으로 돌리면 자동으로 다시 실행한다.
  - 설정: `TUJ_API_RETRIES`, `TUJ_API_BACKOFF_S`, `TUJ_API_BACKOFF_MAX`.
- **도구**:
  - `scripts/run_ablation_batch.py`: 배치 실행과 에러 수집 → `output/ablation/<method>/errors_summary.md`.
  - `scripts/make_table3.py`: Table III 생성(Macro SR, Wilson CI, McNemar, Fisher+Holm).
- **Table II 검증 체계**:
  - `scripts/verify_table2_coverage.py` (팀원 확장): (물체, EE)마다 새 프로세스로 파지·상승·유지를 실행한다. `--all-ees`가 없으면 Reasoner가 feasible로 추정한 조합만 돈다.
  - 검증 전용 probe 레시피: `objects/c*_probes.py`, registry의 `VALIDATOR_EXPERIMENTAL_ENTRIES`. 일반 실행에는 영향 없다.
  - C2_1~C4_2: 팀원이 114조합을 검증했다(64 PASS). 결과는 `docs/ee_gear_coverage_results_20261102.json`, 요약은 `docs/ee_gear_checkpoint_20261102.md`.
  - C1_1/C1_2 probe는 C4_1 패턴을 따른다: 같은 형상의 검증된 레시피를 상속하고, 물체 정보·크기·자세만 바꾼다(handle 3F ← fork_recipe, handle 2F ← fork_2f_c3_2_recipe, 납작한 도구 2F ← spatula_c4_1_recipe, 그 외 ← CatalogRecipe 기본값). 테스트는 `tests/test_c1_coverage.py`.
  - `configs/ycb_mass_gt.json`: YCB 공식 질량.
  - `scripts/vac_gt_admissibility.py`: GT 표면(top-down에서 보이는 점) + YCB 질량을 Full과 같은 vac 규칙에 넣는다. vac 성공 = 시뮬 PASS ∧ GT 규칙 통과. 시뮬은 접촉만 하면 운동학적으로 붙어서, 이 조건 없이는 vac 성공을 셀 수 없다.
  - `scripts/table2_recompute.py`: 1번 표는 논문과 같은 정의(잡힌 수/전체 물체, 괄호 안이 논문 값), 2번 표는 Reasoner 추정 정밀도(✓/추정 feasible). 기호: `!` = ERROR(재실행 필요), `⊗` = vac가 붙었지만 GT 불통과, `*` = 미확정. `docs/*coverage_validation*.json`을 자동으로 읽는다.
- **vac 규칙 근거** (프로젝트 문서 `vac-rule-evidence.md`): Dex-Net 3.0, SuctionNet, Schmalz, Piab, Robotiq. 규칙은 수정하지 않았다. 다공성은 non-porous 가정으로 두고 논문에 명시하기로 했다.
- **수정한 구현 오류**:
  - C1_1 2F의 `catalog_hand_correction` 누락.
  - C1_2 반죽 flex 접촉의 geom id −1 (`catalog_vacuum.object_support_penetration_m`).
  - probe의 PRIMARY 검사 순서.
  - `table2_recompute`: ERROR를 실패로 세던 문제, C1 결과를 읽지 않던 문제, 논문과 다른 분모를 쓰던 문제, c2_2 id 매칭(turkey_1↔turkey_3).
- **C1_1 2F 링키지 초기화** (`profiles.py`, 11/05):
  - C1_1 2F도 2F 링키지 보정 경로를 탄다. 원래는 inner_knuckle −0.196 rad로 범위를 벗어나 PRESHAPE에서 전부 실패했다.
  - 되돌리기: `TUJ_C1_1_2F_LINKAGE_INIT=0` 또는 backups 폴더의 파일.
  - 결과: bottle_distractor 2F PASS. ladle/fork는 CLOSE 접촉 불안정, scissors는 knuckle이 테이블과 충돌. plate 2F는 전과 동일하게 "controller did not converge"로 실패(하네스 한계, 레지스트리도 EXPERIMENTAL).
  - C1_1 Full에서는 Reasoner가 plate를 vac로만 판정하므로 2F 경로를 아예 쓰지 않는다. 즉 Ours에는 영향이 없다.
